SECTION 1 — WHAT THIS DEVICE DOES
================================================================================

VoiceNote AI is a pocket-sized AI voice recorder that:

  1. Records audio via a digital I2S MEMS microphone (INMP441)
  2. Saves the recording as a .WAV file on a MicroSD card
  3. Connects automatically to WiFi on boot
  4. When recording stops, uploads the WAV file to a cloud server over HTTPS
  5. The cloud backend transcribes the audio using OpenAI Whisper
  6. The user views transcripts, AI summaries, and tasks in a web app

User controls:
  - SW2 (power switch)  → slides to turn the whole device ON / OFF
  - SW1 (record switch) → SPDT toggle:
                            flip UP   = starts recording (GPIO8 reads HIGH)
                            flip DOWN = stops recording, saves file, uploads

The firmware is COMPLETE and TESTED. The intern's job is hardware only.
Do NOT modify any code. Do NOT change any GPIO pin assignments.

SECTION 4 — POWER ARCHITECTURE (wire in this exact order)
================================================================================

The TP4056 module handles all charging. The power switch (SW2) only cuts power
to the ESP32 and peripherals — the battery always remains connected to TP4056
so it can charge from USB even when the device is switched OFF.

  USB-C ──────────────────→ TP4056  IN+ / IN−
                                │
                           TP4056  B+ / B−  ←──→  LiPo Battery (always on)
                                │
                           TP4056  OUT+ / OUT−
                                │
                              SW2  (power switch — slides to cut power)
                                │
                         ┌──────┴───────┐
                         │              │
                    ESP32 5V pin    All other modules
                    ESP32 GND       (SD, INMP441)

  TP4056 LED indicators (on the module itself):
    Red  LED lit    = currently charging
    Blue LED lit    = fully charged
    Both off        = no USB power / battery not connected

  IMPORTANT:
    The TP4056 module already includes over-charge and over-discharge protection.
    Do NOT add a second protection circuit — it is redundant and can cause issues.
    Do NOT reverse battery polarity — it will permanently damage the TP4056.

SECTION 6 — PHASE 1: BREADBOARD VERIFICATION
================================================================================

Before designing any PCB, confirm the full system works on a breadboard.
This catches wiring mistakes cheaply. Do not skip this phase.

STEP 1 — Flash the firmware
──────────────────────────────
  Software needed:
    - Arduino IDE 2.x (download from arduino.cc)
    - ESP32 board package installed in Arduino IDE

  Install ESP32 board package:
    Arduino IDE → File → Preferences → Additional Boards Manager URLs:
    Paste: https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
    Then: Tools → Board → Boards Manager → search "esp32" → install

  Board settings in Arduino IDE:
    Board:            ESP32C3 Dev Module
    Upload Speed:     921600
    USB CDC on Boot:  Enabled
    Port:             whichever COM port appears when ESP32 is plugged in

  Open firmware file:
    voice-ai-architecture/firmware/voice_ai_hardware/voice_ai_hardware.ino

  Credentials are stored as environment variables on the server — you do not
  need to edit the firmware. If credentials are needed for testing, ask Ramayana.

  Click Upload. Wait for "Done uploading."

STEP 2 — Wire the breadboard
──────────────────────────────
  Wire exactly as per Section 3.
  Use jumper wires. Power from USB (3.3V from ESP32's onboard regulator is enough
  for breadboard testing — no TP4056 needed yet for this step).

  Breadboard power rail:
    ESP32 3.3V pin → + power rail
    ESP32 GND      → − power rail

  Wire INMP441:
    VDD → 3.3V rail
    GND → GND rail
    SD  → GPIO 3
    WS  → GPIO 4
    SCK → GPIO 5
    L/R → GND rail

  Wire MicroSD module:
    VCC  → 3.3V rail (or 5V if your module needs it)
    GND  → GND rail
    SCK  → GPIO 6
    MOSI → GPIO 7
    MISO → GPIO 2
    CS   → GPIO 10

  Wire SW1 (use any 3-pin switch or simulate with jumper wires):
    Common (middle) → GPIO 8
    One side        → 3.3V
    Other side      → GND

  Wire LEDs:
    GPIO 0 → 220Ω resistor → Green LED → GND
    GPIO 1 → 220Ω resistor → Red LED   → GND

  Insert a MicroSD card (FAT32 formatted) into the module.

STEP 3 — Test
──────────────────────────────
  Open Arduino IDE Serial Monitor at 115200 baud.
  Power the ESP32.

  Expected sequence:
    1. Green LED blinks while connecting to WiFi
    2. Green LED stays ON when WiFi is connected
    3. Serial Monitor shows "WiFi connected"
    4. Flip SW1 UP → Red LED turns ON, Serial shows "Recording started"
    5. Speak into the microphone for 5–10 seconds
    6. Flip SW1 DOWN → Red LED turns OFF
    7. Serial shows "Uploading…" then "Upload successful"
    8. Check web app — recording should appear within 30 seconds

  If anything fails, check:
    - SD card is FAT32 formatted (not exFAT)
    - SD card VCC is correct voltage for your module
    - GPIO 9 is NOT used — it has a hardware pullup on the ESP32-C3 Super Mini
      and causes auto-recording on boot if connected
    - Check Serial Monitor for error messages

STEP 4 — Sign off before moving to PCB
──────────────────────────────────────────
  Get Ramayana's confirmation that the breadboard test passed before
  proceeding to Phase 2. Send a short video of the recording + upload working.

SECTION 7 — PHASE 2: PCB DESIGN IN EASYEDA
================================================================================

Tool: EasyEDA Standard (free, browser-based — easyeda.com)
      Do NOT use EasyEDA Pro (different file format, harder for review)

Board specifications:
  Size:   60mm × 60mm  (fits the 3D-printed enclosure)
  Layers: 2-layer
  Color:  Black soldermask (matches product aesthetic — optional but preferred)

── STEP 1: SCHEMATIC ───────────────────────────────────────────────────────────

Create a new project in EasyEDA. Start with the schematic.

Place these symbols (search EasyEDA library by part name):
  - ESP32-C3-MINI-1 (or generic 40-pin header for Super Mini footprint)
  - INMP441 (or place as 6-pin connector with correct net labels)
  - MicroSD slot (4-pin SPI + VCC + GND)
  - TP4056 module (place as a sub-block with IN, B+/B−, OUT pins)
  - SPDT switch (3-pin)
  - SPSS switch (2-pin)
  - LEDs × 2
  - Resistors × 2 (220Ω)
  - Capacitors × 4 (100µF, 10µF, 100nF, 100nF)

Label all nets clearly:
  +3V3, +5V, GND, I2S_SD, I2S_WS, I2S_SCK,
  SPI_SCK, SPI_MOSI, SPI_MISO, SPI_CS,
  GPIO8, GPIO0, GPIO1, REC_SW, PWR_SW

Run ERC (Electrical Rules Check) — fix all errors before moving to layout.

── STEP 2: PCB LAYOUT ──────────────────────────────────────────────────────────

Component placement order (place in this sequence):

  1. ESP32-C3 Super Mini — CENTER of board
       Orient so antenna end points AWAY from all other components
       (antenna area must be copper-free — see antenna rule below)

  2. INMP441 — TOP-RIGHT AREA, near the top edge
       The microphone opening must align with the mesh hole in the enclosure lid
       Place face-up (mic port facing away from PCB)

  3. MicroSD module — RIGHT EDGE of board
       The card slot opening must align with the right-side cutout in the enclosure

  4. TP4056 module — BOTTOM EDGE, near USB-C side
       The USB-C port must align with the bottom enclosure cutout

  5. SW1 (record toggle) — LEFT EDGE or FRONT EDGE
       Must align with the switch cutout in the enclosure side panel

  6. SW2 (power switch) — adjacent to SW1 on the same edge
       Must align with its cutout in the enclosure

  7. LED1 (green) + LED2 (red) — BOTTOM EDGE
       Must align with the LED holes in the enclosure base

  8. Decoupling capacitors — AS CLOSE AS PHYSICALLY POSSIBLE to their IC VCC pins
       C1 + C2 + C3 → within 3mm of ESP32 VCC pin
       C4           → within 3mm of INMP441 VDD pin

  9. Resistors R1, R2 — between GPIO pads and LED pads

Trace widths:
  Power traces  (+5V, +3V3, GND, BAT lines) : 1.0mm preferred, 0.5mm minimum
  Signal traces (I2S, SPI, GPIO)             : 0.3mm preferred, 0.25mm minimum

Ground plane:
  Bottom layer → full copper pour connected to GND net
  This eliminates most noise on the microphone and SD card lines

Antenna clearance rule (CRITICAL):
  The ESP32-C3 Super Mini has a PCB trace antenna on one short end.
  In EasyEDA, mark a keepout zone around this end:
    - No copper pour
    - No traces
    - No components
    - No ground plane
  Violating this will kill WiFi range.

Mounting holes:
  Add 4 × M2 mounting holes (2.2mm drill, 5mm copper-free pad) at board corners
  These align with the standoffs inside the 3D-printed enclosure

Board outline:
  Draw a 60mm × 60mm closed rectangle on the Edge.Cuts / Board Outline layer

── STEP 3: DRC ─────────────────────────────────────────────────────────────────

Run DRC (Design Rule Check) in EasyEDA.
Target: zero errors, zero airwires remaining.
If any airwires remain, the schematic and layout are out of sync — fix this
before sending for fabrication.

SECTION 9 — PHASE 4: PCB ASSEMBLY AND TESTING
================================================================================

Tools needed:
  - Soldering iron (temperature-controlled, set to 320–350°C for lead-free solder)
  - Solder (0.8mm, lead-free or 60/40)
  - Flux (paste flux helps with small pads)
  - Multimeter
  - USB-C cable
  - MicroSD card (formatted FAT32)
  - Computer with Arduino IDE

STEP 1 — Inspect bare PCB
  Check for shorts, broken traces, missing pads.
  Compare against your EasyEDA layout visually.

STEP 2 — Solder in this order (easiest to hardest)
  1. Resistors R1, R2         (flat, easy)
  2. Capacitors C3, C4        (small ceramics, do these before big electrolytics)
  3. Capacitors C1, C2        (electrolytics — polarity matters, stripe = negative)
  4. LEDs                     (flat side of LED = cathode = GND side)
  5. ESP32-C3 Super Mini      (pin headers or direct solder)
  6. INMP441 module
  7. MicroSD module
  8. TP4056 module
  9. SW1, SW2                 (switches last — they are tall)
  10. LiPo battery connector  (JST 2-pin or solder wires directly)

STEP 3 — Pre-power checks with multimeter
  Before plugging in anything:
  a) Measure resistance between +3V3 and GND → should NOT be 0Ω (would mean short)
  b) Measure resistance between +5V and GND → should NOT be 0Ω
  c) Visually inspect all solder joints under bright light or magnifier

STEP 4 — First power-on
  Connect USB-C (no battery yet).
  TP4056 red LED should light up (charging) or blue (no battery = float state).
  ESP32 onboard LED may blink.
  Open Serial Monitor → confirm WiFi connects → confirm green LED turns on.

STEP 5 — Full function test (same as breadboard test in Phase 1)
  Insert SD card, flip record switch, speak, flip back, confirm upload on web app.

SECTION 11 — COMMON MISTAKES TO AVOID
================================================================================

These are real mistakes that will waste days of your time. Read this carefully.

── WRONG GPIO PINS FROM OTHER SOURCES ─────────────────────────────────────────

  Several AI tools (including ChatGPT) suggest the following — ALL WRONG:

  What ChatGPT says      │  What the firmware actually uses
  ───────────────────────┼──────────────────────────────────
  I2S SD  → GPIO 6       │  I2S SD  → GPIO 3   ← CORRECT
  I2S WS  → GPIO 5       │  I2S WS  → GPIO 4   ← CORRECT
  I2S SCK → GPIO 4       │  I2S SCK → GPIO 5   ← CORRECT
  SPI SCK → GPIO 3       │  SPI SCK → GPIO 6   ← CORRECT

  If you wire using those wrong numbers, the microphone captures silence and
  the SD card fails — and the error messages will look like hardware failures,
  not wiring mistakes. You will waste hours debugging.

  Rule: ALWAYS use Section 3 of this document. Never cross-reference pin numbers
  from any other source without asking Ramayana first.

── DO NOT USE GPIO 9 FOR ANYTHING ─────────────────────────────────────────────

  The ESP32-C3 Super Mini has a hardware-level pullup resistor on GPIO 9.
  This is the BOOT button pin.
  If you connect anything to GPIO 9, the device will behave randomly on boot
  or auto-start recording before you touch any switch.
  GPIO 9 is reserved by the hardware — leave it unconnected.

── DO NOT ADD AN EXTERNAL LDO REGULATOR ────────────────────────────────────────

  ChatGPT recommends adding an AMS1117-3.3 LDO to your design.
  This is wrong for this project.
  The TP4056 module already regulates output voltage.
  The ESP32-C3 Super Mini has its own built-in 3.3V regulator.
  Adding a second LDO creates voltage stacking problems and wastes board space.
  Do not add it.

── DO NOT SKIP DECOUPLING CAPACITORS ───────────────────────────────────────────

  The ESP32 pulls up to 250mA in bursts during WiFi transmit.
  The SD card pulls sudden current during write operations.
  Without decoupling capacitors, you will see:
    - Random ESP32 resets during WiFi upload
    - SD card file corruption
    - Audio noise / hissing
  The capacitors listed in Section 2 are the minimum viable set. Do not remove any.

── FORMAT THE SD CARD CORRECTLY ────────────────────────────────────────────────

  The firmware requires FAT32 format.
  Windows default for cards > 32GB is exFAT — the firmware cannot read this.
  Use a card that is 32GB or smaller, or manually format to FAT32.
  On Windows: right-click the card in File Explorer → Format → FAT32.
  On Mac: Disk Utility → Erase → MS-DOS (FAT).

── DO NOT CONNECT THE BATTERY BACKWARDS ────────────────────────────────────────

  LiPo batteries have red (positive) and black (negative) wires.
  The TP4056 module has B+ and B− pads clearly marked.
  Reversed polarity permanently destroys the TP4056 and may cause the battery
  to swell or vent. Double-check polarity before connecting.

── ANTENNA KEEPOUT IS NOT OPTIONAL ─────────────────────────────────────────────

  If you route copper pour or traces under the ESP32-C3 antenna area,
  WiFi range drops dramatically (sometimes to under 1 metre).
  The firmware relies on WiFi to upload recordings.
  Mark and enforce the keepout zone in EasyEDA before routing.

── DO NOT MODIFY THE FIRMWARE ──────────────────────────────────────────────────

  The firmware is tested and working in production.
  Any change to GPIO numbers, I2S config, SPI config, or upload logic
  requires a full regression test on the breadboard before committing.
  If you think a change is needed, ask Ramayana — do not edit and assume.

SECTION 13 — FIRMWARE REFERENCE (DO NOT CHANGE)
================================================================================

Firmware location:
  voice-ai-architecture/firmware/voice_ai_hardware/voice_ai_hardware.ino

Flash settings in Arduino IDE:
  Board:            ESP32C3 Dev Module
  Upload Speed:     921600
  USB CDC on Boot:  Enabled
  Flash Mode:       QIO 80MHz
  Partition Scheme: Default 4MB with spiffs

The firmware does the following automatically:
  - Connects to WiFi on boot (credentials embedded via environment)
  - Reads GPIO 8 for switch state every loop iteration
  - GPIO HIGH → starts I2S capture, opens WAV file on SD, turns on red LED
  - GPIO LOW  → stops capture, finalizes WAV header, sends heartbeat "idle"
                to backend, then uploads WAV file over HTTPS multipart POST
  - Sends heartbeat every 6 seconds to keep the web app status indicator live
  - Green LED reflects WiFi/online status

Backend endpoint (already deployed on Render.com):
  POST https://voice-ai-da3b.onrender.com/save
  Authentication: X-Api-Key header (stored in firmware as environment variable)
