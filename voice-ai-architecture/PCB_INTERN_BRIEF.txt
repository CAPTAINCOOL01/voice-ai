SECTION 1 — WHAT THIS DEVICE DOES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

VoiceNote AI is a pocket-sized voice recording device that:

1. Records audio via a digital MEMS microphone (INMP441)
2. Saves the recording as a .WAV file on a MicroSD card
3. Connects to WiFi automatically
4. Uploads the WAV file to a cloud backend (Render.com) over HTTPS
5. The cloud backend transcribes it using OpenAI Whisper and stores it
6. The user accesses recordings and AI summaries via a web app

The user controls recording using a 3-pin SPDT toggle switch:
  - Flip UP  → starts recording
  - Flip DOWN → stops recording, saves file, uploads to cloud

There is also a power switch to turn the whole device on/off.

SECTION 2 — COMPLETE COMPONENT LIST
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

U1  — ESP32-WROOM-32 (main microcontroller, WiFi built-in)
        Arduino IDE board: "ESP32 Dev Module"
        WARNING: GPIO6–GPIO11 are connected to internal flash.
        NEVER connect anything to GPIO6, 7, 8, 9, 10, or 11.
U2  — INMP441 (I2S digital MEMS microphone module)
U3  — MicroSD card module (SPI interface, 5V input with onboard LDO)
U4  — TP4056 (LiPo battery charger module with protection, USB-C input)
U5  — XL6009E1 (DC-DC boost converter module, 3.7V → 5V regulated output)
SW1 — SPDT toggle switch, 3-pin (Si 26 3A 250V or equivalent) — recording control
SW2 — SPDT toggle switch, 3-pin (Si 26 3A 250V or equivalent) — power ON/OFF

NOTE: Both switches are the SAME part (Si 26 3A 250V SPDT, 3-pin).
      Buy 2 of the same switch — simplifies sourcing and the PCB footprint is identical.
BAT — 3.7V LiPo battery, 2000mAh single cell, JST PH 2.0mm connector
LED1— Green LED, 3mm or 5mm (status / device online indicator)
LED2— Red LED, 3mm or 5mm (recording indicator)
R1  — 220Ω resistor (current limit for LED1)
R2  — 220Ω resistor (current limit for LED2)
R3  — 100kΩ resistor (battery voltage divider — top leg, BAT+ side)
R4  — 100kΩ resistor (battery voltage divider — bottom leg, GND side)
C1  — 100µF electrolytic capacitor (bulk decoupling on 5V rail near ESP32 VIN)
C2  — 10µF electrolytic capacitor (decoupling near ESP32 VCC)
C3  — 100nF ceramic capacitor (high-freq decoupling near ESP32)
C4  — 100nF ceramic capacitor (decoupling near INMP441 VDD)
C5  — 100nF ceramic capacitor (GPIO34 ADC filter — optional but recommended)
J1  — USB-C connector (or use the one already on TP4056 module)

SECTION 3 — COMPLETE PIN MAPPING (from firmware)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ESP32-WROOM-32 GPIO assignments:

  INMP441 Microphone (I2S):
    GPIO 25 → INMP441 WS   (word select / LRCK)
    GPIO 26 → INMP441 SCK  (bit clock)
    GPIO 35 → INMP441 SD   (data out) — input-only pin, perfect for mic data
    GND     → INMP441 L/R  (set to left channel)
    3.3V    → INMP441 VDD
    GND     → INMP441 GND

  MicroSD Card Module (SPI — VSPI bus):
    GPIO 18 → SD SCK
    GPIO 23 → SD MOSI
    GPIO 19 → SD MISO
    GPIO 5  → SD CS (chip select)
    VIN rail → SD VCC  (5V input — module has onboard LDO; do NOT use 3.3V pin)
    GND     → SD GND

  SW1 — Recording Toggle (SPDT, 3-pin):
    GPIO 4  → Switch COMMON (middle pin)
    3.3V    → Switch PIN A  (flip this way = START recording)
    GND     → Switch PIN B  (flip this way = STOP recording)

  SW2 — Power Switch (SPDT, 3-pin):
    XL6009E1 OUT+ (5V) → Switch COMMON (middle pin)
    ESP32 VIN +
    SD VCC             → Switch PIN A  (ON — 5V flows to all modules)
    NC                 → Switch PIN B  (OFF — leave unconnected)

  LEDs:
    GPIO 2  → R1 (220Ω) → LED1 anode → LED1 cathode → GND  (green, status)
    GPIO 15 → R2 (220Ω) → LED2 anode → LED2 cathode → GND  (red, recording)

  Battery Voltage Monitor:
    BAT+ → R3 (100kΩ) → GPIO 34 (ADC) → R4 (100kΩ) → GND

    GPIO 34 is input-only and ADC-capable. Do NOT connect any other signal here.

    Voltage mapping:
      4.2V (full battery) → 2.1V at GPIO34 → firmware reads 100%
      3.7V (half charge)  → 1.85V at GPIO34 → firmware reads ~58%
      3.0V (empty)        → 1.5V at GPIO34 → firmware reads 0%

    The firmware sends battery % to the backend every 6 seconds.
    The web app displays it as a live battery indicator in the navbar.

  Power:
    XL6009E1 OUT+ (5V) via SW2 PIN A → ESP32 VIN pin
    GND → ESP32 GND pin

SECTION 4 — POWER ARCHITECTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

IMPORTANT: Wire power in this exact order so battery charges even when device is off.

  USB-C ──→ TP4056 IN+ / IN-
               │
            TP4056 B+ / B- ──┬── LiPo Battery (always connected)
                             │
                             └── XL6009E1 IN+ / IN-  (boost draws from B+ directly)
                                       │
                                 XL6009E1 OUT+ (5V) ──→ SW2 COMMON
                                                             │
                                                     SW2 PIN A ──→ ESP32 VIN
                                                                 + SD VCC
                                                     SW2 PIN B ──→ NC
                                                             │
                                                            GND rail

  Battery voltage divider taps from TP4056 B+ (raw battery voltage):
    TP4056 B+ → R3 (100kΩ) → GPIO34 (ADC) → R4 (100kΩ) → GND
  Do NOT tap from XL6009E1 OUT+. That is always 5V and will read as 100% forever.
  Do NOT tap from TP4056 OUT+. Wire directly to the B+ pad (same node as BAT+).

  CRITICAL — set XL6009E1 output to exactly 5.0V before connecting to board:
    Power XL6009E1 alone from a 3.7V source, measure OUT+ with multimeter,
    trim the pot to 5.0V. This step is mandatory — too high destroys the ESP32.

  Why XL6009E1 connects to B+, not TP4056 OUT+:
  - TP4056 OUT+ is the protected output — it includes a current-sense resistor
    and protection FETs. When XL6009E1 draws load current through OUT+, it
    prevents the TP4056 from seeing the battery as fully charged, so the
    charging LED stays red forever and the battery never fully charges.
  - Connecting XL6009E1 to B+ (battery directly) bypasses the protection output
    path. TP4056 can now correctly detect full charge and switch its LED green.

  TP4056 LED indicators:
  - Red LED on module = charging
  - Blue/Green LED on module = fully charged (only works correctly with B+ tap)

SECTION 5 — PCB DESIGN REQUIREMENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Tool: EasyEDA (free, browser-based at easyeda.com)

Board size target: ~60mm × 60mm (to fit the enclosure)

Layer: 2-layer PCB is sufficient

Trace widths:
  - Power traces (VCC, GND, BAT):  0.5mm minimum, 1mm preferred
  - Signal traces (SPI, I2S, GPIO): 0.25mm minimum

Ground plane:
  - Add a copper pour ground plane on the bottom layer
  - This reduces noise on the microphone and SPI lines significantly

Component placement priorities:
  1. ESP32-WROOM-32 — center of board, antenna end pointing AWAY from
     all other components (antenna keepout — see below)
  2. INMP441 — place near top edge (microphone hole in enclosure lid)
  3. MicroSD — place near right edge (slot accessible from side)
  4. TP4056 — near USB-C port edge
  5. Power switch SW2 — near edge for enclosure cutout
  6. Toggle switch SW1 — near edge for enclosure cutout
  7. LEDs — near bottom edge facing the enclosure LED holes
  8. Decoupling caps — place as close as possible to their IC's VCC pin
       C1, C2, C3 → within 3mm of ESP32 VIN/VCC pin
       C4         → within 2mm of INMP441 VDD pin
       C5         → within 2mm of GPIO34 pad

Battery voltage divider (R3 + R4):
  - Place near the TP4056 BAT+ pad and GPIO34 trace
  - Keep the trace from R3/R4 midpoint to GPIO34 short (under 20mm)
  - Route away from I2S and SPI lines to avoid noise coupling into the ADC

Antenna clearance (CRITICAL):
  - ESP32-WROOM-32 has a metal-shielded module with antenna on one end
  - Keep that end of the board free of copper pours, traces, and components
  - No ground plane under or near the antenna area
  - Violating this kills WiFi range

SECTION 6 — ENCLOSURE REFERENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The enclosure is a 3D-printed two-part box (lid + base):

  Lid (top):
    - Circular mesh hole (top-right) → microphone (INMP441 faces up here)
    - Toggle switch cutout (side)
    - Power switch cutout (side)

  Base (bottom):
    - USB-C port cutout (side, for TP4056 charging)
    - MicroSD slot cutout (side)
    - Status LED hole (bottom-right corner, green)
    - Recording LED hole (bottom, red)
    - 4x corner mounting holes for M2 screws

  PCB layers (bottom to top inside enclosure):
    1. LiPo battery (sits in base)
    2. PCB (screwed into standoffs)
    3. Lid closes on top
